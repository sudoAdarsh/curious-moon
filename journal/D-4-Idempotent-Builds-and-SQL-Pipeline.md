# D-4: Idempotent Builds and Assembling the SQL Pipeline

Today we just have to carefully link all our SQL code till now into a `Makefile` which, upon execution, gives us a final database ready with `master_plan`, the `events` table, and efficient lookup tables.

### 1. Writing Idempotent Code

By linking everything into a repeatable build script, even if we mess something up, we can always get back to a safe point—not by rolling back, but by recreating it cleanly from scratch.

This is called an **idempotent** way of writing code: whether you run the script once or multiple times, it always leaves the database in the exact same state without duplicate data or errors—like a bot playing a game for us right up to a certain safe checkpoint.

### 2. The `Makefile` Build Cycle & `clean` Target

Instead of directly executing individual SQL files one by one, we have `Make` assemble a single SQL file called `build.sql`, which gets freshly generated and executed on each `make` cycle:

1. **`clean` target:** We start by cleaning everything up. This target simply deletes the previous `build.sql` file so we can generate a fresh one.
2. **`master` & `import` targets:** We append the schema/table creation for `import.master_plan` and inject the `\copy` command to load the raw CSV data into it (stored initially as `text`).
3. **`normalize` & `all` targets:** We append our normalization script (`normalize.sql`), which extracts the lookup tables and populates the final `events` table, and then execute the assembled `build.sql` against PostgreSQL.

Here is the `Makefile` that ties the pipeline together:

```makefile
DB=enceladus
BUILD=${CURDIR}/build.sql
SCRIPTS=${CURDIR}/scripts
CSV='${CURDIR}/data/master_plan.csv'
MASTER=$(SCRIPTS)/import.sql
NORMALIZE=$(SCRIPTS)/normalize.sql

all: normalize
	psql $(DB) -f $(BUILD)

master:
	@cat $(MASTER) >> $(BUILD)

import: master
	@echo "\copy import.master_plan FROM $(CSV) WITH DELIMITER ',' HEADER CSV;" >> $(BUILD)

normalize: import
	@cat $(NORMALIZE) >> $(BUILD)

clean:
	@rm -rf $(BUILD)
```

### 3. The Final `build.sql`

Here is the complete, idempotent `build.sql` generated by the `Makefile`:

```sql
drop schema if exists import cascade;
create schema import;

drop table if exists events cascade;
drop table if exists teams cascade;
drop table if exists targets cascade;
drop table if exists spass_types cascade;
drop table if exists requests cascade;
drop table if exists event_types cascade;


create table import.master_plan(
  start_time_utc text,
  duration text,
  date text,
  team text,
  spass_type text,
  target text,
  request_name text,
  library_definition text,
  title text,
  description text
);

\copy import.master_plan FROM '/home/adarshu/Documents/Coding/curious-moon/data/master_plan.csv' WITH DELIMITER ',' HEADER CSV;

select distinct(team)
as description
into teams
from import.master_plan;
alter table teams
add id serial primary key;


select distinct(request_name)
as description
into requests
from import.master_plan;
alter table requests
add id serial primary key;


select distinct(target)
as description
into targets
from import.master_plan;
alter table targets
add id serial primary key;


select distinct(spass_type)
as description
into spass_types
from import.master_plan;
alter table spass_types
add id serial primary key;


select distinct(library_definition)
as description
into event_types
from import.master_plan;
alter table event_types
add id serial primary key;


create table events(
  id serial primary key,
  time_stamp timestamptz not null,
  title varchar(500),
  description text,
  event_type_id int references event_types(id),
  target_id int references targets(id),
  team_id int references teams(id),
  request_id int references requests(id),
  spass_type_id int references spass_types(id)
);


insert into events(
  time_stamp,
  title,
  description,
  event_type_id,
  target_id,
  team_id,
  request_id,
  spass_type_id
)
select 
  import.master_plan.start_time_utc::timestamp at time zone 'America/Los_Angeles',
  import.master_plan.title,
  import.master_plan.description,
  event_types.id as event_type_id,
  targets.id as target_id,
  teams.id as team_id,
  requests.id as request_id,
  spass_types.id as spass_type_id
from import.master_plan
left join event_types
  on event_types.description = import.master_plan.library_definition
left join targets
  on targets.description = import.master_plan.target
left join teams
  on teams.description = import.master_plan.team
left join requests
  on requests.description = import.master_plan.request_name
left join spass_types
  on spass_types.description = import.master_plan.spass_type;
```

Using `DROP ... IF EXISTS ... CASCADE` at the top ensures that every run tears down old state cleanly before rebuilding—making our entire pipeline completely idempotent.
